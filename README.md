# Chek Backup

Утилита для Windows, которая каждый день проверяет почтовый ящик
**backup@csl.by** и предупреждает, если резервная копия не сделана.

Программа живёт в системном трее, запускается вместе с Windows и по
расписанию смотрит почту:

* **пришло письмо об ошибке** (в теме или в тексте есть «ошибка», «сбой»,
  «не выполнено», «не работает», `failed`, `error` …) → уведомление
  **«Бэкап не выполнен»**;
* **письма от отправителя нет** за заданное окно (по умолчанию 26 часов) →
  уведомление **«Письмо о бэкапе не получено»** — служба резервного
  копирования, вероятно, не работает;
* **пришло письмо об успехе** → статус ОК (уведомление можно включить);
* **не удалось подключиться к ящику** (нет сети, неверный пароль) →
  уведомление **«Нет связи с почтовым ящиком»**.

Написана на Go + [Fyne](https://fyne.io). Сборка выполняется на GitHub
Actions, готовый `.exe` лежит в артефактах сборки или в Releases.

---

## Установка

1. Скачайте `chek-backup.exe` из раздела **Releases** (или из артефактов
   последней сборки Actions).
2. Положите файл в постоянную папку, например `C:\Program Files\ChekBackup\`.
3. Запустите. Программа появится в трее (синяя иконка конверта) и сразу
   откроет окно настроек — введите параметры IMAP и пароль ящика.

Никаких установщиков и прав администратора не требуется, все настройки
хранятся в профиле пользователя:

| Файл | Назначение |
| --- | --- |
| `%APPDATA%\ChekBackup\config.json` | настройки (пароль зашифрован Windows DPAPI) |
| `%APPDATA%\ChekBackup\chek-backup.log` | журнал работы (ротация при 5 МБ) |
| `%APPDATA%\ChekBackup\state.json` | результат последней проверки |

## Трей

* Иконка меняет цвет: **зелёная** — бэкап выполнен, **жёлтая** — нет письма
  или результат не распознан, **красная** — пришло письмо об ошибке,
  **серая** — проверить не удалось.
* Меню трея:
  * текущий статус и время следующей проверки;
  * **Проверить сейчас**;
  * **Открыть окно состояния** (подробности, список писем);
  * **Настройки…**;
  * **Запускать с Windows** (галочка, реестр `HKCU\…\Run`);
  * **Журнал** (открыть лог);
  * **Выход**.
* Клик по иконке открывает окно состояния; закрытие окна не завершает
  программу.

Уведомления показываются всплывающим сообщением Windows, при необходимости
дублируются окном с предупреждением и звуковым сигналом (всё настраивается).

## Настройки

Вкладка **Почта**:

| Поле | Описание |
| --- | --- |
| IMAP-сервер | например `imap.csl.by` |
| Порт | 993 для SSL/TLS, 143 для STARTTLS |
| Шифрование | SSL/TLS, STARTTLS или без шифрования |
| Логин / Пароль | учётная запись ящика; пароль шифруется DPAPI текущего пользователя |
| Папка | обычно `INBOX` |
| Таймаут | ограничение на сетевые операции |
| Не проверять сертификат | только для самоподписанных сертификатов |

Кнопка **Проверить подключение** проверяет авторизацию и чтение ящика, ничего
не меняя.

Вкладка **Правила**:

| Поле | Описание |
| --- | --- |
| Отправители | фрагменты адресов через запятую (`backup@csl.by`, `@csl.by`). Пусто — любой отправитель |
| Признаки ошибки | регулярные выражения (без учёта регистра), по одному в строке |
| Признаки успеха | то же для успешного завершения |
| Игнорировать письма | письма, которые нужно пропустить (рассылки и т. п.) |
| Только тема | не скачивать и не анализировать текст письма |

Приоритет: если в письме встречается признак ошибки — письмо считается
ошибочным, даже если есть слова об успехе («завершено с ошибками»).
Вердикт выносится по **самому свежему распознанному** письму в окне проверки.

Вкладка **Расписание**: время ежедневной проверки (по умолчанию `09:30`),
размер окна проверки в часах (26 — сутки с запасом), лимит скачиваемых писем,
размер журнала, проверка при запуске, автозапуск с Windows.

Вкладка **Уведомления**: когда показывать уведомления (успех / отсутствие
письма / ошибка), показывать ли окно с предупреждением, нужен ли звук.

## Сборка

### GitHub Actions (рекомендуется)

Workflow `.github/workflows/build.yml` собирает `.exe` на `windows-latest`:

* ставит Go и MinGW-w64 (нужен для cgo, который использует Fyne);
* `windres` встраивает иконку и манифест (DPI, совместимость с Windows 10/11);
* запускает `go vet` и тесты;
* собирает `chek-backup.exe` с флагом `-H windowsgui` (без окна консоли);
* выкладывает артефакт `chek-backup-windows-amd64`.

Чтобы получить готовый релиз, поставьте тег:

```bash
git tag v1.0.0
git push origin v1.0.0
```

Артефакт будет приложен к GitHub Release автоматически.

### Локально (Windows)

```powershell
# нужен Go 1.25+ и MinGW-w64 (например, из MSYS2: pacman -S mingw-w64-x86_64-gcc)
cd assets
windres -i app.rc -o ../cmd/chek-backup/rsrc_windows_amd64.syso -O coff
cd ..
go mod download
go build -trimpath -ldflags "-s -w -H windowsgui" -o dist/chek-backup.exe ./cmd/chek-backup
```

Иконки пересобираются командой `go run ./tools/genicons`.

## Тесты

```bash
go test ./internal/...
```

Логика (разбор IMAP-ответов, кодировки писем, правила классификации,
планировщик, оценка результата) покрыта тестами, в том числе тестом
IMAP-клиента на встроенном тестовом сервере — сеть для них не нужна.

## Структура проекта

```
cmd/chek-backup        точка входа, контроллер, трей-приложение
internal/config        конфигурация, валидация, шифрование пароля (DPAPI)
internal/imapx         минимальный IMAP-клиент (stdlib + TLS), разбор MIME и кодировок
internal/rules         правила классификации писем (регулярные выражения)
internal/checker       логика проверки ящика и формирования вердикта
internal/scheduler     ежедневный запуск по расписанию
internal/state         сохранение результата последней проверки
internal/ui            Fyne: трей, окно состояния, настройки, уведомления
internal/platform      автозапуск, единственный экземпляр, звук, оболочка
internal/logx          журнал с ротацией
tools/genicons         генератор иконок и .ico
assets                 иконка, манифест и ресурсы для windres
```

## Ограничения и замечания

* Поддерживается только Windows (трей, автозапуск, DPAPI). Остальные
  платформы собираются, но трей и автозапуск там не работают — это сделано,
  чтобы логику можно было тестировать на любой ОС.
* Используется обычная IMAP-аутентификация (`LOGIN`). Если ваш сервер требует
  OAuth2 (Office 365, Gmail с обязательным OAuth), включите пароль приложения
  или basic auth для этого ящика.
* Ящик открывается в режиме «только чтение» (`EXAMINE`), письма не помечаются
  прочитанными и не удаляются.
* Программа не хранит письма: скачивается только шапка и, при необходимости,
  текст письма (не более 4 МБ на письмо и не более 25 писем за проверку).

## Устранение неполадок

* **«Нет связи с почтовым ящиком»** — проверьте сервер/порт/шифрование и
  нажмите «Проверить подключение» в настройках; подробности в журнале.
* **«Не удалось расшифровать пароль»** — файл `config.json` скопирован с
  другой учётной записи Windows; введите пароль заново.
* **Не приходят уведомления** — в Windows 10/11 проверьте «Параметры →
  Система → Уведомления» и режим «Не беспокоить»; окно с предупреждением
  можно включить в настройках как гарантированный вариант.
* **Программа не стартует с Windows** — включите галочку в меню трея
  («Запускать с Windows»), она пишет значение `ChekBackup` в
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.
